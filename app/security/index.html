The best security measure KEYDIR has is simplicity. Static pages, no database of personal data in the directory, no payment processing, minimal JavaScript. There is little to break because there is little to attack.

SECTION_01 Our Approach

KEYDIR's security model is built on three ideas:

  • Minimize — we collect the least data possible (see the Privacy Policy) and store none of it in the directory.
  • Defer — the directory is served from static hosting infrastructure maintained by a large provider with dedicated security teams.
  • Disclose — real vulnerabilities get fixed, acknowledged, and thanked, not ignored.

SECTION_02 What We Protect

  • The directory and this site — served over HTTPS only, with no login and no stored user data.
  • The app — account credentials and personal data at app.keydir.in, protected by the hosting platform's authentication and infrastructure.
  • The repository — the open-source codebase on GitHub, with its own security tooling.
  • You — the community, against scams and phishing that misuse the KEYDIR name.

SECTION_04 Your Account

If you use the app with an account, protect it:

  • Use a strong, unique password and do not reuse it across sites.
  • Enable any two-factor authentication the app offers.
  • Never share your credentials, including with someone claiming to be a KEYDIR maintainer — maintainers will never ask for your password.
  • If you believe your account was compromised, report it immediately through the Report Abuse channel.

SECTION_05 Phishing & Scams

⚠
KEYDIR maintainers will never ask you for passwords, OTPs, or payment "to keep your listing live". No one can buy placement on KEYDIR. Treat any such request as a scam and report it.

Scammers sometimes impersonate community projects. Key facts to check:

  • The official directory is keydir.in; the official app is app.keydir.in. Verify the domain before entering credentials.
  • KEYDIR never collects advance payment for listings, flags, or placement.
  • Legitimate communications come from the official email address, officialkeydir.in@gmail.com, or the official GitHub repository.

SECTION_06 Responsible Disclosure

If you find a security vulnerability in the directory, this documentation site, or the app, we would appreciate a responsible report:

  1. Email the details to officialkeydir.in@gmail.com with the subject [SECURITY], or open a private report via GitHub's security advisory feature.
  2. Include a clear description, steps to reproduce, and the impact you observed.
  3. Give us a reasonable period (we suggest at least 30 days) to fix the issue before public disclosure.
  4. Do not access or exfiltrate data beyond what is needed to demonstrate the issue, and do not disrupt the service for others.

SECTION_07 What to Expect

  • Acknowledgement — we confirm receipt of valid reports, usually within a few days.
  • A fix — we work on a resolution and credit you in the project's acknowledgements if you wish.
  • No bounty — this is a volunteer project without a bug-bounty budget. Our thanks, credit, and a place in the changelog are what we can offer.

Testing the live service beyond demonstrating a vulnerability, without coordination, may violate the Acceptable Use Policy. Coordinated, good-faith testing is welcome.

SECTION_08 Contact

Security reports: officialkeydir.in@gmail.com (subject [SECURITY]) or GitHub security advisories on the repository.
